OpenCode：匿名通道已被服务端关闭，改为只支持 API Key

真实端点实测（用本项目 OpencodeProvider 原样打 opencode.ai，非重写假设）：
匿名槽（Authorization: Bearer public）在完整门禁形状下仍一律 403
FreeTierError；请求头逐项消融后全部 403，证明与请求头无关。上游最新版
dsh-codearts-auth@1.3.261015 的服务端事实与本移植完全一致，它自己也不再
自动播种匿名账号。故匿名 403 是服务端现状，不是本移植的缺陷。

据此撤下「免登录」宣传与入口，避免用户添加一条必然失败的通道：

- home.html：删除「免登录添加（免费模型）」按钮；onOpencodeAdd 去掉
  anonymous 形参，留空直接提示；占位符改「sk-…（必填）」；note 改「API Key」
- GatewayServer：管理端点空 key 由「即免登录」改为 400 错误；模型目录改为
  有 key 才列出；匿名槽错误文案指向「请申请 API Key 填入」
- AccountManager/Boot：删除 ensureDefaultOpencodeAccount 播种调用；
  匿名槽标签显示「匿名通道（已失效）」，否则用户看到正常标签却条条失败
- OpencodeProvider：移除远端已下架两条模型 mimo-v2.5-free、
  nemotron-3-ultra-free；类注释改述为「保留形状与指纹代码，上游一旦放宽
  即可恢复，对认证通道无害」
- RegTest：新增下架条目断言（isReachable 必须为 false）
- README/MILESTONES：撤下免登录宣传，改为显式警告块 + 实测证据表，
  新增里程碑 13 记录协议细节、错误分类优先级与本次教训

教训：离线断言只证明实现自洽，证明不了假设与线上一致。未公开行为必须用
真实端点证伪。若只跑离线断言就交付，用户拿到的会是一个「有免登录入口、
点进去条条 403」的包。
